### 1.3 MAVLink 详解（一）：数据帧与消息模型

一句话理解

MAVLink 不是“无人机遥控协议”这么简单，它更像无人机系统里的：

> 一套带大量标准消息定义的轻量级二进制消息总线协议。

### MAVLink协议版本与格式

MAVLink有两个主流版本：**V1.0（明文无签名）** 、**V2.0（可选消息签名）**。

- **V1.0帧格式** ：STX(0XFE)→LEN→SEQ→SYSid→COMid→MSGid→payload→CRC，**无签名、明文传输、无完整性校验**。
- **V2.0帧格式** ：STX(0XFD)→LEN→INC_FLAGS→CMP_FLAGS→SEQ→SYSid→COMid→MSGid→payload→CRC→SIGNATURE（可选），新增**消息签名、向后兼容**功能，但默认关闭签名，易降级至V1.0。

### MAVLink核心安全缺陷

1. **身份认证缺失** ：V1.0无任何认证机制；V2.0签名默认关闭，开启后也存在**密钥管理漏洞、签名绕过**风险。
2.  **数据明文传输**：即使开启V2.0签名，payload数据仍明文传输，攻击者可直接读取飞行状态、位置、电量等敏感数据。
3. **消息易伪造/重放**：无随机数、时间戳防重放机制，攻击者嗅探合法消息后，可直接重放或篡改部分字段后发送，飞控无法识别。
4. **协议降级风险**：V2.0设备为兼容V1.0，可被强制降级至V1.0，导致签名机制失效，安全防护归零。

```python
from pymavlink import mavutil
from collections import Counter
import time

connection = mavutil.mavlink_connection('udpin:127.0.0.1:14550')

print('[*] waiting for heartbeat...')
connection.wait_heartbeat()
print('[+] heartbeat:', connection.target_system, connection.target_component)

counter = Counter()
last_report = time.time()

while True:
    msg = connection.recv_match(blocking=True, timeout=1)
    if msg is None:
        continue

    name = msg.get_type()
    if name == 'BAD_DATA':
        continue

    counter[name] += 1

    if time.time() - last_report >= 5:
        print('\n=== last interval / cumulative message counts ===')
        for k, v in counter.most_common(15):
            print(f'{k:28s} {v}')
        last_report = time.time()
```

### 1.4 MAVLink 详解（二）：命令、任务、参数与状态

第一节是“帧”，第二节要理解“交互协议”。

#### 1. Command Protocol

典型流程：

```text
Sender
  |
  | COMMAND_LONG
  v
Flight Controller
  |
  | COMMAND_ACK
  v
Sender
```

必懂：

- `MAV_CMD_*`；
- ACK；
- accepted / denied / failed 等结果；
- command 和 telemetry 不一样。

#### 2. Mission Protocol

典型上传不是“发一个航点就完事”：

```text
GCS                       FCU
 |--- MISSION_COUNT ------>|
 |<-- MISSION_REQUEST_INT -|
 |--- MISSION_ITEM_INT ---->|
 |<-- MISSION_REQUEST_INT -|
 |--- MISSION_ITEM_INT ---->|
 |<------ MISSION_ACK ------|
```

安全研究必须理解这个状态机，否则你只看到“很多消息”。

#### 3. Parameter Protocol

参数实际上影响了大量安全相关行为：

- failsafe；
- arming checks；
- communication；
- estimator；
- flight modes。

因此参数访问也是重要安全面。

#### 动手实验：只打印关键协议消息

```python
from pymavlink import mavutil

m = mavutil.mavlink_connection('udpin:127.0.0.1:14550')

interesting = {
    'COMMAND_LONG', 'COMMAND_ACK',
    'MISSION_COUNT', 'MISSION_REQUEST', 'MISSION_REQUEST_INT',
    'MISSION_ITEM', 'MISSION_ITEM_INT', 'MISSION_ACK',
    'PARAM_VALUE'
}

while True:
    msg = m.recv_match(blocking=True, timeout=1)
    if msg and msg.get_type() in interesting:
        print(msg)
```

1. 查看参数；
2. 创建一个三航点 Mission；
3. 上传 Mission；
4. 回到终端观察消息序列。

### 1.5 ROS 系统入门到 MAVROS

#### ROS核心安全缺陷

ROS为简化开发、提升兼容性，默认采用**开放设计**，存在三大核心安全隐患：

1. **无身份认证机制**：ROS Master对节点注册无身份校验，任意节点（恶意/合法）均可接入系统，注册话题、发布消息、调用服务，无权限隔离。
2. **通信数据明文传输**：ROS话题、服务数据均以明文传输，无加密、无完整性校验，攻击者通过网络嗅探即可获取全部通信数据，甚至篡改数据后重放。
3. **话题/服务无访问控制**：ROS无细粒度权限管理，任意节点可订阅所有话题、调用所有服务，无"最小权限"约束，单点突破即可影响整个系统。

```python
import time

PORT = 14660
m = mavutil.mavlink_connection(f'udpin:127.0.0.1:{PORT}')

print(f'[*] listening on localhost:{PORT}')

    now = time.time()

    last[key] = now

        f'sys={msg.get_srcSystem():3d} '
        f'comp={msg.get_srcComponent():3d} '
        f'type={msg.get_type():20s} '
        f'dt={delta:.3f}'
    )
```

实验：位置跳变检测器（使用你自己的测试数据）

下面脚本不控制无人机，只读取本地 MAVLink 并根据连续 GLOBAL_POSITION_INT 做粗略速度检测：

```python
from pymavlink import mavutil
from math import radians, sin, cos, sqrt, atan2
import time

m = mavutil.mavlink_connection('udpin:127.0.0.1:14550')

prev = None
R = 6371000.0

def distance_m(lat1, lon1, lat2, lon2):
    p1, p2 = radians(lat1), radians(lat2)
    dp = radians(lat2 - lat1)
    dl = radians(lon2 - lon1)
    a = sin(dp/2)**2 + cos(p1)*cos(p2)*sin(dl/2)**2
    return 2 * R * atan2(sqrt(a), sqrt(1-a))

while True:
    msg = m.recv_match(type='GLOBAL_POSITION_INT', blocking=True, timeout=2)
    if not msg:
        continue

    now = time.time()
    lat = msg.lat / 1e7
    lon = msg.lon / 1e7

    if prev:
        dt = now - prev[0]
        d = distance_m(prev[1], prev[2], lat, lon)
        speed = d / dt if dt > 0 else 0
        if speed > 80:  # 示例阈值，不是通用飞行规则
            print(f'[ALERT] impossible-looking jump: {speed:.1f} m/s')
        else:
            print(f'[OK] {speed:.1f} m/s')

    prev = (now, lat, lon)
```

重点不在 80 这个数字，重点在“物理约束可以成为安全信号”。

### 4.5 阶段二：航线篡改与任务完整性（二）——写检测器

Mission 指纹思想

把任务标准化后计算 hash：

```text

↓

↓

↓

```

Python 基础版：

```python
import hashlib
import json

mission = [
    {"seq": 0, "cmd": 16, "lat": 47.0, "lon": 8.0, "alt": 20},
    {"seq": 1, "cmd": 16, "lat": 47.0001, "lon": 8.0001, "alt": 30},

    mission,
    sort_keys=True,
    separators=(',', ':'),
```

### 6.2 先逆向一个 Toy Drone Protocol

为了合法、安全地练完整流程，我们自己造一个未知协议。

### generator.py

```python
import os
import random
import struct

# frame:
# AA 55 | LEN | TYPE | SEQ | X(int16) | Y(int16) | BAT(uint8) | CRC8
# 学习时假装你不知道格式。

def crc8(data):
    c = 0
    for b in data:
        c ^= b
    return c

os.makedirs('captures', exist_ok=True)

seq = 0
for label, typ, xbase, ybase in [
    ('idle', 1, 0, 0),
    ('forward', 2, 100, 0),
    ('left', 3, 0, -100),
    ('button_a', 9, 0, 0),
]:
    with open(f'captures/{label}.bin', 'wb') as f:
        for _ in range(30):
            x = xbase + random.randint(-3, 3)
            y = ybase + random.randint(-3, 3)
            bat = random.randint(70, 90)
            payload = struct.pack('<BBhhB', typ, seq & 0xff, x, y, bat)
            body = bytes([len(payload)]) + payload
            frame = b'\xaa\x55' + body + bytes([crc8(body)])
            f.write(frame)
            seq += 1
```

运行：

```bash
mkdir -p ~/uav-sec-lab/code/toyproto
cd ~/uav-sec-lab/code/toyproto
python generator.py
xxd captures/idle.bin | head
xxd captures/forward.bin | head
```

现在**先把代码盖住**，只看 bin，当作真实抓包。

你的逆向任务

Task A：找帧头

搜索重复：

```bash
xxd -p captures/idle.bin | tr -d '\n' | grep -o 'aa55' | wc -l
```

Task B：找帧长

看看 `aa55` 后的 byte 是否稳定。

Task C：找 counter

对齐 10 个 frame，找哪一列近似 +1。

Task D：动作差分

比较：

```bash
cmp -l captures/idle.bin captures/forward.bin | head -30
```

更好的做法是写 Python 对齐帧后按 byte offset 统计。

### 6.3 写通用“字节变化率分析器”

```python
from pathlib import Path
from collections import Counter

FRAME_LEN = 11  # 逆向过程中这是你的假设，不一定正确

def frames(path):
    data = Path(path).read_bytes()
    return [data[i:i+FRAME_LEN] for i in range(0, len(data), FRAME_LEN)
            if len(data[i:i+FRAME_LEN]) == FRAME_LEN]

for file in Path('captures').glob('*.bin'):
    fs = frames(file)
    print('\n', file)
    for off in range(FRAME_LEN):
        values = [f[off] for f in fs]
        unique = len(set(values))
        common = Counter(values).most_common(3)
        print(f'offset={off:02d} unique={unique:02d} common={common}')
```

你会看到某些 offset：

- 永远固定；
- 每帧变化；
- 随动作变化；
- 缓慢变化。

这四类特征分别很像：

```text
magic/header
counter/timestamp
command/control field
battery/sensor
```

### 6.4 AI 在协议逆向里真正有用的地方

不要直接扔 5 MB hex 给 AI。

最好给 AI：

```text
1. 20 个已经对齐的 frame
2. 每个 frame 的实验动作标签
3. byte offset 变化率
4. 你的猜测
5. 问它“提出可证伪的假设”
```

好问题：

```text
Offset 0-1 永远是 AA55；offset2 永远是 07；offset4 每帧+1；
在 forward 样本里 offset5-6 接近 100，idle 接近 0。
请给出三个字段布局假设，并告诉我下一步如何设计实验区分它们。
```

坏问题：

```text
这串 hex 是什么？帮我破解。
```

真正的逆向是“实验科学”，AI 是假设生成器，不是魔法解码器。
